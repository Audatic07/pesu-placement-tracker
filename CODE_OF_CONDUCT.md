# Code of conduct

This project is maintained by students, for students, about a subject people
are genuinely anxious over. That shapes what is expected here.

## What is expected

Be straightforward and be kind. Disagree with the argument. Assume the person
on the other side is trying to make the thing better, because they almost
always are.

Most contributors here will be learning as they go — this may be the first
real codebase someone has opened. "Why did you do it this way" is a good
question when it is a question. It is not a good question when it is a verdict
wearing a question mark.

## What is not acceptable

- Harassment, insults, or personal attacks, including in code review.
- Comments about someone's placement outcome, package, CGPA, or employability.
  This is a placement app; that particular cruelty is close at hand and it is
  never acceptable here.
- Publishing anyone's private information — a name, an SRN, a package, a
  screenshot of a record — in an issue, a pull request, a commit message, or a
  test fixture. This is the one rule where a single violation is enough.
- Sustained disruption: reopening settled decisions, or pressing a point after
  the maintainers have ruled on it.

## Reporting

Report privately to the repository owner through GitHub — open a private
security advisory if the incident also involves exposed data, or contact the
owner directly through their GitHub profile. Do not open a public issue about
a person.

Reports are read by the maintainers, kept confidential, and answered. Expect
that to take days rather than hours; this is run by students during their own
placement season.

## Consequences

Maintainers may edit or remove content, close a thread, or block an account.
For anything involving another student's private data, removal is immediate and
is not a negotiation.

## Scope

This applies in the repository — issues, pull requests, discussions, commits —
and to anyone representing the project elsewhere.
